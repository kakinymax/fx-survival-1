確認日: 2026-10-07 UTC。作業の正本は [Issue #12](https://github.com/kakinymax/fx-survival-1/issues/12)。Webの基準は main `90c758b65c074ea735f544e88ca31770e9298c21`、モバイル試作の読み取り基準は PR #11 / `26cdf5b74bd9b47377c45856f381b03683cc3951`。

## 修正した問題

| 問題 | 確認した影響 | 対策 |
| --- | --- | --- |
| 保存レコードの任意のCPUセリフを受け入れる | 認証済み利用者が自分のレコードに `cpuQuotes` のオブジェクトを保存すると、試合画面の文字列化が例外となり表示が停止する | 保存前に項目・型・文字数を検証。過去に保存された不正なセリフも画面では無視し、過去の結果を書き換えない |
| IDの暗黙の型変換、参加者・進退の不完全な検証 | 配列のID、未知のCPU人格、CPU入りの対面、別表記の進退ID、進退のない早期終了を受け入れる | 文字列ID、連続した参加者ID、現行の対面／ソロ構成、全生存者の進退と最終進退の一致、許可された保存項目を検証 |
| JSON解析エラーの内容をTRIPの応答へ返す | 不正なリクエストの一部がエラー文へ反映される。通信の読み取りエラーは処理外へ漏れる | 固定エラーで400を返す。JSONのメディアタイプ・UTF-8を検証し、ストリーム失敗を処理 |
| 本文の読み取りに時間上限がない | サイズ上限内の遅いクライアントが読み取りを保持できる | 試合128,000バイト／TRIP2,000バイトの上限を維持し、15秒で408。キャンセル完了を待たずに拒否 |
| ブラウザの防御設定が不足 | スクリプト注入や外部への送信が生じた際の追加防御がない | Workerの成功・エラー応答にCSP、nosniff、Referrer-Policy、Permissions-Policy。スクリプト・通信・フォントは同一オリジンに限定。インラインスクリプト、eval、外部埋め込みを禁止 |
| 開発用の推移的依存の既知の警告 | mainのnpm監査で7パッケージ、モバイル試作で10パッケージに警告 | sharp、Drizzleの間接esbuild、モバイルXcodeツールの間接uuidを修正版へ限定するoverrides。現行Wrangler／Drizzle／Capacitorの直接バージョンは維持 |

CPUのセリフと名前はHTMLとして実行せず、エスケープする。画面の寸法調整に必要なインラインCSSはCSPで許可する。ゲームの確率・12ラウンド・BigInt精算・CPU判断・秘密注文の受け渡しは変更していない。

## 認証とデータの境界

- APIの所有者は `oai-authenticated-user-id` ヘッダーからのみ取得する。SQLは値をバインドし、すべての読み書きで所有者を絞る。同一ゲームIDの別内容は409で拒否し、既存の試合を上書きしない。
- このヘッダーを信用できるのは、認証済みのSites入口が利用者からの値を除去・上書きする場合だけ。Workerを直接インターネットへ出したり、公開の別入口でヘッダーを通したりしない。独立ホスティングへ移す場合は、署名を検証する認証を先に実装する。
- 既存Sites公開先へ未ログインのGETとランダムな偽のユーザーIDヘッダー付きGETを送ったところ、いずれも入口で401だった。他の実在利用者のIDやデータにはアクセスしていない。ログイン済みのヘッダー上書きやすべての別入口まで検証した結果ではない。
- 書き込みはOriginとFetch Metadataを検査する。別Origin、`Origin: null`、`Sec-Fetch-Site: cross-site` を拒否する。既存の同一オリジン通信とOriginを付けないCLIを維持する。CORSで別Originを許可しない。
- 個人の試合・戦績APIは `Cache-Control: no-store` を維持する。トークン・秘密鍵・環境設定の誤コミットを減らすignoreを追加。追跡ファイルの秘密情報パターン検索では該当なし。ただし履歴全体の秘密情報監査ではない。

## 残る運用上の制約

1. **公開・取り込み**: この文書と修正の作成だけでは公開版へ反映されない。mainへの統合、Sitesの再公開、Pagesの再配布、PR #11への取り込みを別々に記録する。WorkerのCSPヘッダーは静的PagesやオフラインのWebViewへ自動では付かない。
2. **大量アクセス**: 履歴集計は所有者の全試合を読む。本文の制限は大量リクエストや大量保存の対策にはならない。利用者増加時は認証入口のレート制限・保存上限・集計コスト監視を設定し、実際の負荷を測る。現時点で分散レート制限の設定は確認していない。
3. **結果の真正性**: クライアントが作った試合を算術・進行の整合性で検証する。妥当な架空の試合や意図的な乱数操作を証明付きで排除する方式ではない。利用者本人の履歴用途を前提とし、将来、対外ランキングや景品を導入する場合はサーバー側進行／署名記録が必要。
4. **モバイル**: 試作は同梱資産を使い、外部サイトをWebViewへ読み込む設定がなく、オンライン戦績は未接続。AndroidのFileProviderは非公開だが共有パスが外部領域／キャッシュ全体になっている。共有機能を追加する前に必要な専用フォルダへ絞る。Androidのバックアップが有効なため、正式保存方針に沿って名前・戦績のバックアップ対象を明示する。今回は端末の保存・署名方針を変更しない。
5. **確認範囲**: ソースレビュー、再現用テスト、npm監査、ローカルWorker/D1とブラウザ、公開入口の未認証GETを確認。iOS／Androidの新しい実機ビルド、OS依存ライブラリ全体、認証済み本番操作、プラットフォームの内部設定は未検証。
