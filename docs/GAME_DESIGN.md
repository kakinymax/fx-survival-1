# ルールと設計方針

2026-10-04時点の実装を要約する。詳細は[README](../README.md)と実装を参照し、以後の変更では本書も更新する。

## ゲームの核

100万円から始め、買い／売り、1〜100倍のレバレッジ、いつ資産を確定するかを選ぶ。相場を予測する情報は与えず、リスク量と降りる時期を自分で選ぶことを中心にする。高倍率の追加ボーナスや、資産額到達による自動勝利は設けない。

| 項目 | 現行仕様 |
| --- | --- |
| 対面 | 2〜6人、1台の端末を受け渡す。3人以上を推奨 |
| CPU対戦 | 人間1人とCPU3人 |
| 初期資産 | 全員100万円 |
| ゲーム長 | 最大12ラウンド、取引中が0人になれば早期終了 |
| 注文 | 必ず買い／売りと整数1〜100倍。全資産を基準に取引額を計算 |
| 相場方向 | 全員共通、上昇／下落50:50 |
| 資産確定 | 精算後に永久離脱。資産を固定し、勝者になる資格は残る |
| 勝利 | 正の最終資産が最大の人。同額なら全員同率勝利 |
| 全員0円以下 | 勝者なし。損失比較の順位表示は優勝を意味しない |

一時休止、部分投資、負債を追加しての再参入はない。12ラウンド終了時の生存者は追加の値動きなしで自動確定する。

## ステージと抽選

ステージは開始時に全員共通で選び、ゲーム中には変更しない。通貨名はゲーム用の味付けで、実在の値動きを再現する設定ではない。

| ステージID / 表示名 | 第1サイコロ1〜5（通常） | 第1が6、第2が1〜3（通常） | 第1が6、第2が4〜6（ギャップ） |
| --- | --- | --- | --- |
| `classic` / ベーシック | 0.1 / 0.2 / 0.3 / 0.5 / 0.8% | 1.0 / 1.0 / 1.5% | 2 / 5 / 10% |
| `usdjpy` / ドル円 | 0.1 / 0.1 / 0.2 / 0.3 / 0.5% | 0.8 / 0.8 / 1.0% | 1.5 / 3 / 5% |
| `tryjpy` / トルコリラ円 | 0.2 / 0.4 / 0.6 / 1.0 / 1.5% | 2 / 2 / 3% | 5 / 10 / 20% |

サイコロは各面が等確率。第1の6は急変判定であり、ギャップ確定ではない。ギャップ確率は全ステージ1/12。`classic` は旧名「クラシック」と同じIDで、過去の名称や保存データを一括置換しない。

## 精算と記録

- 取引額 = 現在資産 × レバレッジ。方向が的中すれば利益、逆行すれば損失。
- 通常相場で理論損失が現在資産以上なら、0円でロスカット。負債は生じない。
- ギャップ相場は理論損失をそのまま適用する。負の残高は負債退場、0円も退場。利益側に上限はない。
- 金額は1,000円単位の整数を文字列で保持し、BigIntで演算。精算後の残高を四捨五入し、ちょうど半分は絶対値が大きくなる側へ丸める。
- 現在・確定資産は公開。最高到達資産、最大取引額、最終状態、ラウンドログを残す。
- 順位は資産の降順、同額なら同順位（1位、2位、2位、4位）。確定・退場した人も含め、表示のソートで手番順は変更しない。

## 操作と演出

1. 本人だけで注文を入力する。前の人の確定後は次の人の未選択画面へ直接進み、最後の人の確定で全注文を公開する。
2. アプリ抽選は、方向をボタンで抽選して結果を見せ、別のボタンで第1サイコロを抽選する。第1が6なら第2も別ボタン。精算ボタンまで自動精算しない。
3. 対面の進退は全員がその場で同時宣言し、一括画面で記録する。進退は隠さない。最初は未選択、全員続行のショートカットから個別変更できる。
4. スマホでは操作とスクロールを少なくし、固定の確定ボタンが内容を隠さないようにする。5〜6人の精算では画面下に残る結果の案内を維持する。

注文入力時は前ラウンドの確定ログから、上昇／下落・変動率・通常／ギャップと、本人の買い／売り・倍率・実際の損益を表示する。前回倍率をスライダーの中央に置き、その下に「前回の相場」「前回の注文」を分け、方向・率と損益の数値を強調する。対面では手番プレイヤーのIDで本人の結果を参照し、現在の未公開注文は含めない。ソロの「前回○倍」は倍率だけを復元し、売買は本人が選ぶ。初回や前回結果がない場合は枠を出さない。相場の確率や抽選、精算は変更しない。

第1が6だった時だけ、第2の確定済み結果に合わせて今回の足を約1秒で伸ばす。演出前に抽選結果を保存し、最後に変動率と通常／ギャップを表示する。再読み込みで振り直さず、動きを減らす設定では待ち時間を省く。実物の出目入力は既存の進行を維持する。

相場履歴は開始指数100からの全員共通の値動き。レバレッジ・プレイヤー資産はチャートに使わない。足は1ラウンドの始値と終値で、実際に存在しないヒゲや逆方向への揺れを足さない。ROUND TRENDは白地に黒いドット描画・同梱のピクセル字体を使用し、足は上昇を緑、下落を赤で塗りつぶす。塗りの外側に黒の1px枠線を付け、細い足でも色を残す。白地でも見やすい濃さにし、過去の足と演出中の足で配色を揃える。縦軸は開始指数100を縦中央に置く上下対称の5目盛りとし、基本2刻み、必要な値幅が大きい時は文字が重ならないよう4・6など2の倍数へ広げる。確定済みの足と急変用の予約範囲を両側へ収め、演出中に縮尺を変えない。横方向の縦点線は常に4区間とし、R01〜R04は各区間1枠（全4枠）、R05〜R08は各区間2枠（全8枠）、R09〜R12は各区間3枠（全12枠）へ切り替える。足とラウンド番号は各小枠の中央へ揃え、未到達の枠には足を描かない。同じ4ラウンドのまとまりで目盛りの最大文字幅が同じ間は横位置を保ち、過去の足・縮尺を演出中に固定する。トレンド画像の外寸は維持し、幅480未満では高さ164px、それ以上では204pxとする。内部の文字は整数倍の拡大と狭い文字間隔で密度を上げ、広い画面は見出し・統計値・軸の数値・ラウンド番号を拡大する。ROUND TREND・MARKET INDEX・MIN／MAX／LASTの3行はグラフ枠の左辺へ揃える。MIN／MAX／LASTはMARKET INDEXと同じ文字サイズで1行に置き、狭い幅でも大きな指数が収まるよう字間を調整する。見出しは右上のラウンド番号と重ならない整数サイズに収める。縦軸の最も長い数字の左余白は2pxとし、数字とグラフ枠は8px、画像右端は12pxを保つ。大きな値幅で目盛りの桁数が変わる場合も左余白を保つようグラフ左辺を調整するが、演出中は予約済みの範囲から決めた位置を固定する。Gは統計値の下の専用段に配置し、グラフ枠は文字が欠けたり重なったりしない範囲に収める。

## CPUと長期戦績

CPUの人格は `steady`（堅実派）、`rival`（対抗派）、`gambler`（勝負師）。公開資産・順位・残りラウンドで判断し、人間の入力前に注文、人間の進退前にCPUの進退を確定・保存する。セリフの変更で判断確率や乱数呼び出し回数を変えない。

ゲームは12ラウンドのまま、保存済み試合を積み重ねる。生涯戦績・歴代記録・TRIP・モード別・殿堂入り・振り返り・CPUの通算・自己ベストは保存ログから再構築する。CPUの名前と人格IDを分け、人間本人、他の人間、CPUを混同しない。対面の名前からログイン本人を推測しない。

永久の初期資産アップ・ロスカット耐性など、周回数で有利になる変更は現在の設計に含めない。新しい戦略・確率・ステージ・チャレンジ等を追加する場合は、別タスクとして目的と影響を整理する。
