公開ソースはpages/font-change-previewブランチの/ (root)です。

ROUND TRENDの縦の点線は常に4区間を維持します。R01〜R04は各区間1ラウンド（全4枠）、R05〜R08は各区間2ラウンド（全8枠）、R09〜R12は各区間3ラウンド（全12枠）に切り替え、足とラウンド番号を各小枠の中央へ揃えます。R05とR09では右側に3ラウンド分の余白ができますが、未到達の足は描きません。同じ4ラウンドのまとまりと急変演出中は足の横位置を保ち、R12は従来の4区間×3ラウンドの配置です。

足は参照画像の緑#7fe0be（上昇）・赤#ff909c（下落）で塗りつぶし、外側に黒の1px枠線を付けます。細い足でも色を残し、過去の足と急変演出中の足で同じ配色を使います。縦軸は開始指数100を基準に基本2刻みとし、値動きが大きい時は4・6など2の倍数へ広げて文字の重なりを防ぎます。USD/JPYの5%下落では102・100・98・96・94の目盛りになります。黒い見出し・点線・字体・角丸・ギャップGの位置を維持し、相場値・抽選・精算・履歴・演出の条件と長さを変更していません。

前回の注文画面改善も含みます。R02以降、「前回○倍」を1倍〜100倍の中央に配置し、その下に「前回の相場」「前回の注文」の2行を表示します。本人の確定結果をIDで参照し、ソロの前回倍率ボタンは倍率だけを復元します。100倍の入力欄も24pxの字体で3桁とカーソルが収まり、＋／−・直接入力・キーボード操作を維持します。この注文画面の検証記録はIssue #6にあります。

npm run build、market-rasterの5テスト、market-candle-browser-checkが成功しました。ユニット検証はR01〜R12の区間内の整列、同じ4ラウンドの間の横位置固定、空き枠に未来の足がないことを確認。ローカルWorkerのブラウザ検証は対面／CPUのR01/R02/R05/R07/R09/R12と既存の急変演出・抽選・通常／ギャップ・再読み込み・ルート復帰・reset・早送りを確認しています。

配布HTMLを320×568、390×600、390×844、1280×900でブラウザ検証しました。R05/R07/R09と偶数ラウンドを含む4区間の点線の実際の画素、足の黒枠が区間境界内に収まること、4ラウンドの間の横位置固定、指定の緑赤の実際の画素、R05/R07/R09/R12の急変演出中に過去の画素と縮尺が固定されること、抽選1回、再読み込みで履歴不変、角丸、操作との重なり・横はみ出し・JavaScriptエラーなしを確認しました。従来の縦軸の2刻みと偶数間隔も維持しています。公開対象SHAと公開後の検証結果はIssue #8を参照してください。

index.htmlはフロントをIIFEにまとめ、同梱WOFFをFontFaceに直接登録した単独HTMLです。英数字はFX Trend Pixel、日本語はDotGothic16。後者のライセンスをOFL.txtとHTML内に収録しています。
対面・CPU対戦、秘密注文、方向/変動率抽選、確定結果に沿う急変演出、精算を試せます。
GitHub Pagesは静的ページなので、Worker/D1や認証付き戦績APIは実行されません。戦績のオンライン保存、生涯戦績、ランキング、TRIP等の通信機能は未接続です。保存成功を模擬する処理はありません。
