# FXサバイバル（仮）

基本ルール v1.0 に基づく、1台を受け渡して遊ぶ2〜6人の対面モードと、1人でCPU3人と対戦するモードがあるブラウザゲーム。

ゲーム画面のソースは `dist/`。相場抽選・CPU判断・精算は従来どおりブラウザ内で行い、ゲームの途中記録は localStorage に保存します。完了した試合の戦績だけを、ログイン中のユーザーごとにアプリ側のD1へ保存します。

ローカル起動は `npm ci` → `npm run build` → D1の未適用マイグレーションを適用 → `npm start -- --port 4173`。最初のマイグレーションは `WRANGLER_LOG_PATH=.wrangler/logs/wrangler.log node node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_dusty_wiccan.sql` です。適用済みのファイルは再実行しません。ローカルの保存API検証では `oai-authenticated-user-id` をテスト用HTTPヘッダーで付与します。本番ではSitesが認証済みのヘッダーを付与し、認証のない保存要求は拒否します。

戦績機能はPhase 1〜7まで対応。終了時に `schemaVersion: 1` の確定レコードを一度作り、FINAL RESULTSと保存APIの両方で同じオブジェクトを使います。ゲームID・開始日時（旧保存は不明）・終了日時・ステージ・対戦形式・抽選方式・ラウンド数・人間/CPU・勝者・全員の最終状態と金額・全ラウンドログ・最大倍率・100倍/50倍以上の使用回数・最大1ラウンド利益/損失・最大ドローダウンを残します。金額はすべて1,000円単位の文字列。最大損失とドローダウンは正の金額で、ドローダウンは各時点までの最高資産からの減少額の最大値（負債を含む）。同率勝利は全勝者のID、勝者なしは空配列です。CPUの種類は名前とは別に保存し、ソロの本人だけ `ownerPlayerId` を設定します。対面では全員を記録しますが、誰がログイン本人かは推測しません。

同じユーザー・ゲームIDの保存は冪等で、確定済みの内容は上書きしません。保存失敗時は未送信の試合だけを一時的な送信待ちデータとしてブラウザに残し、再試行・再読み込み・次のゲーム開始後も同じIDで送信します。成功すると送信待ちデータは消えます。中断した試合は戦績に数えません。D1スキーマは `db/schema.ts`、変更は `npm run db:generate` で生成する `drizzle/` の追加マイグレーションで管理します。

注文は全員の確定後に公開。精算後の進退は全員で同時に宣言し、精算画面で一括記録・確定。資産は常時公開。実物の鉛筆・サイコロの入力と、暗号学的乱数によるアプリ抽選に対応します。通常の0円ロスカット、ギャップの負債、永久離脱、12ラウンド自動確定、同率勝利、勝者なしを扱います。

金額は1,000円単位の整数を文字列で保存し、BigIntで演算。精算後の残高を最も近い1,000円に丸め、ちょうど半分は絶対値が大きくなる方向に四捨五入します。最高資産・最大取引額・各ラウンドの結果を記録します。入力中に再読み込みやアプリ切替をすると、同じプレイヤーの入力画面で未確定の入力をリセットします。

計算・ゲーム進行の検証: `npm test`。

ゲーム全体の字体は、トレンドグラフと同じ5×7ドットの英数字「FX Trend Pixel」と、日本語の「DotGothic16」を組み合わせています。フォントは `dist/fonts/` に同梱し、外部のフォントサービスへ接続せず、説明・入力・ボタン・戦績・ランキング・TRIP・SVG内の文字にも適用。DotGothic16はSIL Open Font License 1.1で、著作権表示とライセンスを `dist/fonts/OFL.txt` に収録しています。通常のビルドにフォント生成は不要です。英数字の字形を変更した場合のみ、PythonのfontToolsがある環境で `python3 scripts/build-pixel-font.py` を実行してWOFFを更新できます。

抽選画面のトレンドグラフは白黒2値の画素で描画します。上昇は白抜き、下落は黒塗り、ギャップは専用行の「G」で表示し、上部のMIN／MAX／LASTと重ねません。縦軸の目盛りと間隔は整数（1・2・5・10・20…）で、端数を含む実際の始値・終値・変動率は変更しません。外枠は8pxの角丸。スマホでは表示幅に合わせて画素を作り、ラウンドの文字だけを必要に応じて間引き、過去の足はすべて残します。MIN／MAX／LASTと今回のGは演出終了後に結果を反映します。

アプリ抽選の同じ枠に、開始指数100から続く過去の相場履歴と今回の足を最大12ラウンド分表示します。今回の足は前ラウンドの終値から始まり、第1サイコロが1〜5なら結果表示時に即座に追加。6の場合だけ、急変判定ボタンを押した後に約1秒のロウソク足演出を表示します。確定済みの方向と実際の第2サイコロの変動率を使い、過去の足は静止したまま今回の足だけを伸ばします。履歴とステージで起こりうる最大値動きを収めた縮尺を抽選前に決め、演出中・結果表示時に抽選結果で縮尺を変えません。架空のヒゲや逆方向への揺れは付けず、演出終了後に変動率と通常／ギャップを表示します。今回の足は表示専用で、従来の精算時に一度だけ履歴へ記録します。結果は演出前に保存し、再読み込みでは再抽選・演出の再生をせず同じ結果を表示。動きを減らす設定では待ち時間を省きます。実物サイコロは従来の即時精算のまま。スマホ表示と演出・履歴の連続性・再読み込み・早送りの検証は、ローカルWorker起動後の `node tests/market-candle-browser-check.cjs` で行います。

WebMCP対応ブラウザでは公開状態の取得と参加者設定からの開始だけを提供します。秘密の注文を読み取るツールはありません。

精算結果の相場表示の横には、全員共通の相場履歴を最大12本のミニローソク足で表示します。開始指数100に各ラウンドの±変動率を複利で適用し、資産やレバレッジはチャート計算に使いません。1本が1ラウンドの始値・終値を示すヒゲなしの足で、上昇は緑、下落は赤、最新は枠、ギャップは小さな印。タップで拡大し、ラウンド別の始値・終値・変動率・出目を確認できます。結果画面の出目は計算詳細でも確認できます。チャートは保存済みの精算履歴から毎回描き直すため、以前のゲームや早送りしたCPU対戦にも対応し、抽選や進退を変更しません。

全員共通のステージを開始時に選択できます。ベーシック（旧称クラシック）は、小さな値動きと大きな急変を組み合わせた基本のステージ。名称変更後もステージIDは `classic` を維持し、既存の保存済み記録は書き換えません。ドル円は通常0.1〜1%、ギャップ1.5 / 3 / 5%。トルコリラ円は通常0.2〜3%、ギャップ5 / 10 / 20%。通貨のイメージを使ったゲーム用の設定です。方向の50:50とギャップ発生率1/12は全ステージ共通です。アプリ抽選・実物入力・ルール表示は同じ表を使用します。ステージ情報がない以前の保存データはベーシックとして継続します。

精算画面で全員が「せーの」で進退を宣言し、各人の結果欄の続行／資産確定ボタンで一括記録します。最初は未選択。「全員続行で記録」のショートカットでまとめて続行にでき、個別に資産確定へ変更できます。選択途中の記録も公開情報として保存し、全員分を記録してから一度だけ確定。確定前は資産や最終状態を変更しません。以前の個別進退入力で途中まで記録した内容は、同じラウンドの一括画面に引き継ぎます。

秘密の注文は確定後に次の人の初期状態の入力画面へ直行し、最後の人の確定後に自動公開。アプリ抽選は、注文公開から相場方向を抽選して結果画面で停止し、次のボタンで第1サイコロを抽選します。6の場合は、値動きの同じ画面で急変判定を別途抽選。値動き確定後に「精算して結果を見る」で精算します。追加画面は方向の結果と値動きの結果の2つだけ。各抽選値を表示演出の前に保存するため、抽選中の再読み込みでも同じ結果画面に復帰し、振り直しや自動精算はしません。旧版の抽選済み保存データも、値動きの結果を保持して精算ボタンを待ちます。実物入力の進行は従来どおりです。ゲーム終了時は精算と最終成績を一画面に表示します。

スマホの注文画面ではラウンド・ステージ・現在プレイヤーをコンパクトに表示し、注文確定と進退確定のボタンを画面下に固定します。レバレッジは直接入力・±・スライダーを併用。進退は資産と選択を横に並べた一覧で記録し、注文や計算の詳細は展開して確認できます。全員の現在／確定資産は公開したまま、最高資産・最大取引額だけを詳細へ移しています。

CPU対戦は開始画面の「1人でCPU対戦」から。堅実派（1〜15倍中心）、対抗派（15〜50倍中心）、勝負師（50〜100倍中心）の固定3人と同じステージで遊びます。CPUは公開された資産・順位・ラウンド数だけを使って判断し、買い／売りは50:50。人間の注文を入力する前にCPUの注文を保存し、精算時には人間の進退選択前にCPUの進退を保存します。再読み込みやアプリ切替でもCPUの選択は変わりません。人間の進退選択はワンタップで確定し、CPUの選択を同時に公開。結果と進退に性格に応じた短いセリフを表示し、履歴にも残します。自分が資産確定・退場した後は同じ抽選ボタンで観戦するか、最後まで早送りできます。早送りはすでに抽選した値を保持し、同じ相場・精算ルールでCPUの残りの取引を進めます。CPU対戦でも最大12ラウンド、資産確定者を含む同率勝利・勝者なしを適用します。

戦績画面は開始画面の「戦績」、またはFINAL RESULTSの「戦績を見る」から開きます（`/#stats`）。本人を確実に識別できる `ownerPlayerId` の人間プレイヤーだけを生涯戦績に集計し、名前の変更でも同じ本人として扱います。現在の対面記録は本人未指定なので、履歴には残しますが本人の累計へ合算しません。CPUの資産も合算しません。

`GET /api/statistics` は認証済みユーザーの保存済みレコードを25件ずつ全件走査し、集計を毎回再構築します。直近10件の履歴表示上限は、生涯集計件数の上限ではありません。同一日時はゲームIDで順序を決めます。生涯の累計金額はBigInt、平均は1,000円単位で四捨五入、優勝率は小数1桁。同率優勝は優勝1回、元本以上にはちょうど元本、元本割れには0円/負債を含みます。資金枯渇回数には `empty` と `cut` の両方を含み、最大負債/損失/ドローダウンは正の金額で表示します。未保存データから累計を作らず、取得失敗時は再読み込みを表示します。

Phase 2の索引は `drizzle/0001_jazzy_kang.sql`。ローカルで未適用なら、最初と同じD1コマンドの `--file` をこのファイルに変更して適用します。適用済みの0000/0001は再実行しません。生涯集計と最近の履歴は保存レコードだけで再構築可能で、別の永続累計値は持ちません。新しい指標がない以前のレコードは保存ログから補完し、相場計算やCPU判断をやり直しません。


歴代記録は戦績画面の「歴代記録」タブ（`/#records`）から。利益・リスク・損失・生存の17項目について上位3件を掲載します。「あなた」は本人が関連付けられたCPU対戦のみ、「人間全体」は対面を含む全人間、「CPU」はCPUのみ。人間全体で同じ名前を同一人物とは扱いません。各記録に金額/回数・名前・ステージ・対戦形式・日時・保存済み試合へのリンクを付けます。各試合の倍率使用回数と、生涯の倍率使用回数は区別します。

金額はBigIntで比較。利益率は `(最終資産 − 初期資産) / 初期資産` を分数のまま比較し、表示だけ小数1桁に丸めます。同値は同順位（1位、1位、3位）。表示枠内では終了日時、ゲームID、プレイヤーIDで順序を決め、最良値の全同記録件数も表示します。損益・回数等が0の候補は掲載しませんが、最高最終資産は0円/負債も含めて実際の記録を掲載します。

連続増加は1ゲーム内の利益が正の連続ラウンド数（0で途切れる）。最高からの転落額は `最高到達資産 − 最終資産` で、途中で回復したゲームでも途中の減少を残す最大ドローダウンとは別です。維持した利益は、正の利益を残し、最終資産が最高到達資産に等しいゲームのみ。最小資産での優勝/元本割れ優勝は正の確定資産の最小値で、同率優勝も含みます。負債退場なし連続ゲーム数は本人/同じCPUタイプが参加したゲームを時系列で計測し、負債で途切れます。0円終了は途切れず、対面の本人未指定ゲームやCPU不参加ゲームは数えません。名前では人物やCPUタイプを連結しません。連続記録には最後の試合と開始日時を付けます。

`GET /api/records` はPhase 2と同じ認証済み所有者の全履歴走査から集計します。D1に別のランキング値を保存せず、各項目の上位3件と同記録件数だけをリクエスト中に保持します。既存レコードの変更/再精算やスキーマ変更はありません。自己ベストの近くには本人の生涯損益も表示します。

`GET /api/matches/:id` は所有者の試合だけを返します。他ユーザーの記録と存在しない記録は同じ404。保存済みの試合詳細（`/#match/:id`）は確定レコードから全参加者の結果、全ラウンドの注文・取引額・損益・進退・出目・相場チャートを読み取って表示します。現在のゲームを置き換えず、再抽選/再取引/再保存の操作もありません。最近のゲーム履歴からも開けます。読み込み中/取得失敗/該当記録なしはそれぞれ明示し、取得失敗時には再試行できます。


TRIP A/Bは戦績画面の「TRIP」タブ（`/#trips`）から。初期状態は未開始で、表示のためのGETでは設定を作りません。各メーターの「計測を開始」で開始し、以後のリセットは確認してから行います。名前は20文字まで変更可能で、名前変更では計測期間を変えません。A/Bの期間は独立しており、各メーターで対象ゲーム数、投入元本相当、最終資産合計、累計損益、優勝回数、資金枯渇/ロスカット、負債退場、最高最終資産、最高到達資産、最大負債、最大取引額、開始日時、最初の対象ゲームへのリンクを表示します。

本人のCPU対戦のみを、保存済みレコードの終了日時がTRIPの開始日時より厳密に後であることを条件に集計します。同時刻と開始前に終了した試合は除外し、開始前から進行していた試合でも終了が後なら含めます。未送信だった古い試合を後から保存しても新しい区間に入りません。本人未指定の対面とCPUの資産は合算しません。金額/回数はPhase 2の生涯集計を区間内の保存履歴に適用するだけで、TRIP専用の累計は保存しません。同率優勝、0円終了、負債、旧レコードの指標補完も同じ計算を使用します。

設定はD1の `trips` テーブルに所有者・メーターID・スキーマバージョン・名前・開始日時・直前の保存ゲームID・更新番号を保存します。メーターIDは文字列で、将来の複数の名前付きメーターへ拡張できる形ですが、現在のUI/APIはA/Bのみです。`GET /api/trips` は開始した区間内の全履歴を既存の所有者/終了日時索引で走査し、対象の最初の本人ゲームIDも計算します。元の履歴、ランキング、生涯戦績をリセット/削除しません。別端末でも同じ設定を使います。

`PUT /api/trips/:id` は `reset` / `rename`、期待する更新番号、リクエストIDを受け取ります。開始時刻はサーバーが決め、クライアントからの指定は受け付けません。D1のトランザクションで更新番号を比較し、別端末の変更が先に入った場合は409と再読み込みを案内します。同じリクエストの再試行では時刻/更新番号を増やさず、応答だけが届かなかったリセットでも再度リセットしません。通信失敗時の名前入力と未確認の操作は画面内で保ち、同じ操作で再試行します。認証、同一オリジン、操作/名前/IDの検証、2KBのJSONサイズ制限も設けています。

Phase 4の追加マイグレーションは `drizzle/0002_sparkling_invisible_woman.sql`。既存のmatchesテーブルや適用済み0000/0001は変更しません。ローカルで未適用なら同じD1コマンドの `--file` に0002を指定して適用します。計測開始/リセット/名前変更/過去試合の表示はゲーム状態を変更せず、相場、CPU判断、精算には変更を加えません。


モード別戦績は戦績画面の「モード別」タブ（`/#modes`）から。ベーシック・ドル円・トルコリラ円の本人のCPU対戦を比較します。未プレイのモードは件数0、率・平均・最大損益は「—」。CPUや本人未指定の対面記録は含みません。今後追加/廃止されたステージも、保存済みIDごとに別枠で表示し、最新の保存済みステージ名を使います。相場やCPU判断を再実行しません。

各モードでゲーム数、累計/平均損益、優勝回数/率、負債退場回数/率、資金枯渇/ロスカット回数、最大1ゲーム利益/損失、平均最大レバレッジ、平均最大取引額を表示します。最大利益/損失は最終資産−初期資産の正/負の最大値（損失は正の額、負債含む）。各ゲームの最大倍率/取引額を平均するため、ラウンド数や取引回数で重みを付けません。同率優勝は1回、金額はBigInt、平均は1,000円単位、倍率/率は小数1桁に四捨五入。

`GET /api/modes` は所有者の保存済み全ゲームを既存の25件ページ走査で読み、生涯集計と同じ計算を各ステージに適用します。取得失敗時は部分集計を表示せず再読み込みを案内します。追加の累計テーブル/キャッシュやマイグレーションは不要。Phase 1〜4のデータ、TRIP設定、ゲーム進行・計算・CPUロジックを変更しません。


殿堂入りは戦績の「殿堂入り」タブ（`/#legends`）から。大逆転、天国から地獄、億り人、一撃3倍、全損、最大負債更新、元本割れ優勝、25倍以内で優勝、100倍で優勝の9種類を保存済みレコードだけから自動判定します。追加得点/倍率ボーナスはありません。本人・人間全体（対面含む）・CPUを分け、出来事の種類で絞り込めます。1人の1ゲームを1枚のカードにまとめ、該当した出来事、名前、最高/最終資産、終了日時、保存済みステージ、対戦形式、判定の根拠と試合詳細へのリンクを表示します。

大逆転は途中残高が初期資産の50%より厳密に小さいこと、天国から地獄は最高資産が初期資産の5倍以上かつ最終資産0以下、億り人は最高/最終資産が100,000単位（1億円）以上。一撃3倍は正の精算前残高から精算後残高が3倍以上になった最初のラウンドです。全損は最高100万円以上かつ最終0円で、負債は含めません。各優勝条件は正の残高と保存済み勝者IDで判定し、同率優勝も対象。25倍以内で優勝は実際の取引があり最大倍率25以下、100倍で優勝は100倍使用回数が1以上です。

最大負債更新は選択対象ごとに終了日時/ゲームID順で厳密な過去最大を更新したゲームを記録し、その時点の直前最大負債も表示します。同額の後続ゲームは更新なし。1ゲーム内は最大負債額の同額者全員が対象です。最初の負債も含め、後に最大額が更新されても過去の更新ゲームを残します。本人未指定の対面を本人に合算したり、名前だけで人物をつないだりしません。

`GET /api/legends` は `scope=self|human|cpu`、`event=all|出来事ID`、任意の `cursor` を受けます。認証済み所有者の全履歴を既存索引で25件ずつ走査し、件数と20件のページを作ります。履歴の集計を20件で打ち切らず、「続きを見る」で該当する全記録にアクセスできます。カーソルは対象/種類/終了日時/ゲームID/プレイヤーIDを検証し、別条件への流用を拒否。最大負債の更新は逆時系列走査の単調スタックで再構築し、以前の記録を相場ルールで再精算しません。過去の指標が未保存なら既存のログ集計で補完します。判定バージョンは1。新しい累計・殿堂テーブルやマイグレーションは不要です。

殿堂入り・試合詳細・追加ページの読込は現在のゲームを変更しません。通信失敗時の再読み込み、追加ページだけの再試行、保存未確認の試合の再送に対応。ゲームの相場、倍率、CPU判断、精算・負債・資産確定とPhase 1〜5のデータは変更しません。


長期戦績の振り返りは「生涯戦績」にまとめています。1ゲームの最高最終資産と生涯損益を並べ、単発の最高額と全ゲームの収支を同時に確認できます。最大取引額・負債退場回数・倍率使用回数は既存の生涯集計を使用します。

「取引の振り返り」では100倍の取引の利益/損失/増減なし回数、取引損益合計、1取引平均損益を表示します。利益/損失は方向の的中ではなく、保存された精算損益が正/負かで判定し、端数処理で0になった取引は「増減なし」。通常ロスカットとギャップ負債も実際に精算された損失を含みます。「ほかの倍率の取引成績」を展開すると1〜25倍・26〜49倍・50〜99倍も確認できます。各取引は一つの区分だけに属します。

別に、1回でも100倍を使ったゲーム/一度も使わなかったゲームを比較します。対象ゲーム数、ゲーム全体の累計/平均損益、優勝回数、負債退場回数、最高最終資産を掲載します。ここでは100倍以外の取引も含めてゲーム全体を数えるため、「100倍の取引だけの損益」とは異なります。未プレイの平均/最高額/損益は「—」、回数は0です。戦略の推奨や警告を付けず、本人の実際の結果だけを表示します。

Phase 7の集計は `GET /api/statistics` の同じ全履歴走査で行い、本人が関連付けられた人間の保存済みログだけを使います。CPU・本人未指定の対面・保存未確認の試合は含めません。100倍を使ったゲーム/使わなかったゲームの集計は既存の生涯集計をそのまま適用し、金額はBigInt、平均は1,000円単位。過去の保存済み取引ログで再構築でき、別の累計や新しいテーブル、マイグレーションはありません。ゲーム計算・相場抽選・CPU判断は変更しません。

試技を受けた操作・表示の改善として、注文画面に通常相場の試算を追加しています。ベーシック0.5%・ドル円0.3%・トルコリラ円1.0%を例に、選択中の倍率での資産の増減を表示。タップすると、そのステージの通常・ギャップの各値動きについて、的中後／逆行後の資産を確認できます。試算は既存の `settle` を使い、端数処理・ロスカット・負債を含めます。次の相場を予想せず、抽選やCPU判断には影響しません。買い／売りの入力・倍率・取引額・試算は320×568と390×600の標準表示でスクロールなしに収まります。

ソロの2ラウンド目以降は、本人が直前に実際に使用した倍率を「前回 ○倍」で呼び戻せます。各注文の初期倍率は1倍、方向は未選択のまま。呼び戻しは明示操作のみで、CPUの倍率や対面の他人の注文は使いません。終了画面の「同じ設定で再戦」は確定済み試合レコードのステージ・対戦形式・抽選方法・名前を使い、別ID・100万円・新しい注文で開始します。設定を変える場合は従来の設定画面へ。未保存の前試合も既存の再送待ちに保持し、再戦で履歴を消しません。

ソロの早送り後は、飛ばしたラウンドから最新の首位交代・最大の利益・最大の損失を最大3件、終了画面に表示。資産確定した人も順位比較に含め、確定済みのラウンドログから読み取るだけで再精算・再抽選はしません。精算結果を見た後に早送りした場合、その既読ラウンドは対象外です。5〜6人分の対面精算では、固定ボタンの上に画面下へ続く結果の人数を表示し、スクロール・画面サイズ変更・進退入力に追従します。全員分が表示範囲に入れば案内は空になります。入力済みの選択とフォーカスは維持します。

100倍使用の有無による戦績比較には、負債退場と併せて0円退場（ロスカットを含む）を表示。既存の `fundsDepleted` 集計を使用し、借金と区別します。CPUのセリフは元本割れ・元本維持・利益確定・公開順位・端数処理後の増減に対応。CPUの倍率選択・離脱確率・乱数の使用回数は変更せず、過去に保存したセリフも書き換えません。追加テーブル・マイグレーションはありません。

改善項目の検証は `tests/play-extras.test.mjs` と `tests/play-extras-browser-check.cjs` にまとめています。後者はローカルWorker/D1を起動した上で実行し、試算・前回倍率・6人のスクロール案内・早送りログ・再戦・通信失敗時の前試合の保存・0円退場の表示を確認します。

ソロの終了画面には、最高最終資産・最高到達資産の自己ベスト通知を最大2件表示します。勝敗欄にも更新件数の小さな目印を表示。初回は「初記録」、過去の値と同額なら更新なし。最終資産と最高到達資産は別々に比較するため、負債で終わった試合の最高到達資産だけが更新される場合もあります。CPUや本人未指定の対面は比較に含めません。

自己ベストは保存成功後に `GET /api/matches/:id/bests` で確認し、対象ゲームより前の保存済みソロの本人だけを比較します。終了日時・ゲームID順で比較し、現在のゲーム自身や後のゲームは除外。再読み込みでも同じ計算を使い、未保存の試合が再送待ちに残っている間は比較を保留します。通信失敗には再確認ボタンを用意し、確認中でも再戦できます。通知や自己ベストの累計を別保存しません。

生涯戦績には折りたたみの「CPUの戦績」を追加しています。堅実派・対抗派・勝負師それぞれの対戦数、優勝数、負債退場数、最高最終資産、累計損益を表示。同率優勝は1回、累計損益は各試合の最終資産から初期資産を引いた合計です。人間の同名プレイヤーは含めず、保存されたCPU人格IDで集計。全ゲームを25件ずつ走査し、`GET /api/statistics` の既存走査と併せて計算します。未プレイの最高・損益は「—」。

開始前のソロのCPU紹介には、保存済みの前回結果に沿った一言を表示します。負債退場・資金枯渇・元本割れ・元本維持・利益を残した終了・優勝／同率優勝を区別。過去の名前変更にも影響されず、終了日時・ゲームIDで人格ごとの最新試合を探します。紹介用の `GET /api/cpu-careers` は同じ集計を使い、読込や再試行で名前入力・現在のゲーム・CPUの秘密注文を変更しません。読み込みを待たずに対戦を開始できます。

以上の読み取りは認証済み所有者の履歴だけに限定し、ブラウザに通算値を保存しません。既存レコード、CPUの判断や抽選、ゲームバランス、ロウソク足の演出は変更せず、新しいテーブル・マイグレーションもありません。`tests/career.test.mjs` と `tests/career-browser-check.cjs` で全履歴の検算、アカウント分離、保存の失敗と再送、古い応答の無視、スマホ／200%文字表示を検証できます。
